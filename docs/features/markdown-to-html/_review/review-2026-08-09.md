## Resolved findings from the initial review

- **[stage-1] Full-document output omits required metadata** — `src/entities/conversion/serialize.ts:13`; AC: AC-09; the wrapper lacks the responsive viewport metadata and stable `Markdown Preview` title required by the criterion. Emit the exact strict wrapper and update the serializer test to assert it byte-for-byte.
- **[stage-1] Unavailable profile storage can crash initialization** — `src/shared/browser/draftStorage.ts:28`; AC: AC-06; accessing `window.localStorage` occurs outside any guard, although browser policy can throw during property access, bypassing the required current-tab fallback. Acquire both storage capabilities inside guarded adapter logic and return a typed fallback state.
- **[stage-1] Failed autosaves never produce the required warning** — `src/shared/browser/draftStorage.ts:39`; AC: AC-06; profile write failures are swallowed and `scheduleSave` exposes no outcome, so the widget cannot announce session-only retention after a quota or permission failure. Return or publish a typed persistence result and keep the warning visible while fallback retention is active.
- **[stage-1] Clear recreates retained storage entries** — `src/view/widgets/ConverterWidget/ConverterWidget.tsx:36`; AC: AC-08; clearing changes Markdown to an empty string, which retriggers the unconditional autosave effect and writes empty profile/tab entries after `drafts.clear()` removed them. Suppress autosave for the clear transition or make empty input remove storage, then test after the timer elapses.
- **[stage-1] Fallback adds an unapproved persistent store** — `src/shared/browser/draftStorage.ts:35`; AC: AC-06; every save writes Markdown to `sessionStorage`, while the accepted data model and ADR-0004 define `localStorage` as the sole persisted value and runtime memory as fallback. Retain fallback content only in module memory and communicate its tab-only lifetime through typed state.
- **[stage-1] Transformation details are not grouped by type** — `src/view/components/SanitizationNotice.tsx:14`; AC: AC-05; the notice renders one flat list rather than details grouped by removal/change category with per-category counts. Aggregate diagnostics by category and list every source position under its category.
- **[stage-1] Full-GFM behavior is not genuinely proven** — `tests/unit/conversion/parse.test.ts:7`; AC: AC-02; the claimed test covers only strikethrough, one table, and one task-list item, omitting fenced code blocks and the remaining official GFM/CommonMark behavior in both rendered surfaces. Add a comprehensive official-spec fixture matrix and UI assertions for preview and generated HTML.
- **[stage-1] Browser-profile isolation has no end-to-end test** — `tests/browser/converter-workflow.spec.ts:3`; AC: AC-07; the persistence workflow reloads one page in one browser context and never proves a separate browser profile/context cannot access the retained draft. Save in one isolated `BrowserContext`, open a second clean context, and assert it starts empty without a cross-profile request.

All eight initial findings were fixed in subsequent feature commits and verified by the expanded unit and browser suites.
